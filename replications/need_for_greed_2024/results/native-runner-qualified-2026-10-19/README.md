# Bounded native runner qualification

The public `run_native.py` command executes one exact deposited Need for Greed configuration. It pins all nine author Python source files and the original ZIP, preserves native field precedence, and changes only the logfile path. A required 1–1,800-second GNU timeout bounds the native process, with ten seconds of kill grace. Output directories must be new.

Real CLI verification covers four workflows: baseline completion, sweep completion, forced native timeout, and duplicate-output rejection. Both successes reach native extinction at tick 136 and reproduce all 137 original reference observations byte-for-byte. The timeout returns 124, preserves its terminal receipt and partial trajectory, and writes no success result. The duplicate attempt leaves every existing output file unchanged.

`verify_runner.py WORKSPACE NEW_OUTPUT` repeats these checks with real original configurations and the pinned engine. No simulation rule or timestep horizon is shortened. The one-second timeout is an explicit failure-path check, not a scientific result. Runtime versions and binary hashes are recorded in each manifest.

The native inputs duplicate already qualified control inputs for end-to-end verification, so they add no unique-input or paper-completion credit. This does not qualify an arbitrary interpreter or prepare a fleet launch. Aggregate spending limits, recovery, and admission coordination remain separate batch requirements.
